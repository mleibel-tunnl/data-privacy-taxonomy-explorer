# CLAUDE.md

Project context for Claude Code. Read `NOTES.md` for the reasoning behind these
rules; this file is the short version.

## What this is

A single-file, offline interactive sunburst over the Fideslang privacy taxonomy.
Rebuilt from source data because the IAB Tech Lab's own "Taxonomy Explorer" is a
static SVG with no underlying chart.

## Hard rules

- **Never edit `index.html`.** It is generated by `scripts/build.py` from
  `src/shell.html` + `data/fides_taxonomy.json`. Edit the shell, then rebuild.
- **Never edit `data/*.json` or `data/*.csv` by hand.** Regenerate with
  `scripts/fetch_taxonomy.py`.
- **Keep it single-file and offline.** No CDN links, no `fetch()`, no npm
  dependencies in the page. It must open from `file://` with no network. Data is
  inlined at build time for exactly this reason — `fetch()` on `file://` is
  CORS-blocked.
- **No chart library in the page.** The arc math is deliberately hand-rolled
  (~40 lines). If a change genuinely needs D3, raise it rather than quietly
  adding a 280 KB inline dependency.

## Build

```bash
python scripts/fetch_taxonomy.py   # only when bumping the fideslang version
python scripts/build.py            # after every src/shell.html change
```

## Where things are in `src/shell.html`

| Concern | Function / selector |
|---|---|
| Palette + theming | `.viz-root` custom properties (`--s1`…`--s8`, surfaces, text) |
| Flat list → tree, leaf weights, hue seeding | `build()`, `assignColor()`, `hueOf()` |
| Angular extents, ring assignment | `layout()`, constants `R0`, `RW`, `maxRings` |
| SVG arc geometry | `arcPath()` |
| Draw pass (rebuilds `svg.innerHTML`) | `render()` |
| Hover tooltip | `svg` `mousemove` handler, `#tip` |
| Side panel | `showDetail()` |
| Breadcrumbs | `drawCrumbs()` |
| Taxonomy tabs, search, table, theme | bottom block after `/* taxonomy picker */` |

## Conventions

- Wedge angle = **leaf count** beneath a node, not term count.
- Hues are seeded at the first level with ≥3 children; rings above that are
  grey. Data Categories only has 2 roots, so a naive "hue = top-level branch"
  rule paints it one color.
- Categorical hues are assigned in **fixed slot order and never cycled**. Past 8
  branches, use a second lighter *band* of the same hues (see `assignColor`).
- Any palette change must be re-validated for colorblind separation — don't pick
  hues by eye. Three light-mode hues are already under 3:1 contrast, which is
  why slice labels and the table view are required relief.
- Plain ES5-ish JS in an IIFE, no build tooling for the page itself. Keep it
  that way unless there's a reason not to.

## Verifying a change

There are no tests yet. At minimum, before calling a change done:

1. `python scripts/build.py`
2. Open `index.html`; check the console is clean.
3. Exercise all three tabs, a zoom-in and zoom-out, a search with hits and one
   with none, the table view, and dark mode.

A Playwright smoke test covering those steps would be a good first test to add.
